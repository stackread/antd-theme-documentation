# Colors

One rule decides almost every colour on these 72 pages.

## Rule A

**The level depends on the size of the surface, not on its meaning.**

A meaning - success, warning, risk - exists at four strengths. Which one a
component takes is decided by how much of it there is:

| level | where | example |
|---|---|---|
| BASE | a large surface | a callout, a whole panel |
| LIGHT | a small enclosed surface | a badge, a tag |
| FILLED | a saturated mark | a health dot, a filled button |
| text / border | a line or a word | error text, a strong border |

A warning callout is BASE and a warning tag is LIGHT - same meaning, different
level, because one is a paragraph and the other is a word.

Getting this backwards produces the mistake that looks like a colour bug and
is a level bug: `#FACB3D` on `#FFF7E2` was yellow on cream, because a tag took
the raw meaning where it should have taken LIGHT.

### The one exception

Yellow. On a light background, white text on `#FACB3D` is unreadable, so a
filled warning surface carries dark text (`#6A4906`) rather than the inverse
text every other meaning uses. The exception is reproduced as measured,
inconsistency included - the warning icon uses `#825803` rather than the
`#6A4906` the rule would predict, and that is reproduced too.

## The levels, live

Read from the running document, not transcribed. Switch the appearance and the
values follow.

```tsx interactive
import React from 'react';
import { Flex, Typography } from 'antd';

const meanings = [
  ['Primary', '--ant-color-primary-bg', '--stackread-light-primary', '--ant-color-primary', '--ant-color-primary-text'],
  ['Success', '--ant-color-success-bg', '--stackread-light-success', '--ant-color-success', '--ant-color-success-text'],
  ['Warning', '--ant-color-warning-bg', '--stackread-light-warning', '--ant-color-warning', '--ant-color-warning-text'],
  ['Risk', '--stackread-risk-bg', '--stackread-risk-light', '--stackread-risk-filled', '--stackread-risk-text'],
  ['Danger', '--ant-color-error-bg', '--stackread-light-error', '--ant-color-error', '--ant-color-error-text'],
  ['Neutral', '--ant-color-info-bg', '--ant-color-info-bg', '--ant-color-info', '--ant-color-info-text'],
];

const levels = ['BASE', 'LIGHT', 'FILLED', 'text'];

/*
 * Read from the ELEMENT, not from the root.
 *
 * Ant Design does not put its variables on `:root` but on a `css-var-*`
 * element per component. A field here inherits them and colours correctly -
 * `getComputedStyle(document.documentElement)` sees none of that and returned
 * an empty string for every `--ant-*`. The surface was right, the label
 * beneath it was empty.
 */
const useValue = (name) => {
  const ref = React.useRef(null);
  const [value, setValue] = React.useState('');

  React.useEffect(() => {
    const read = () => {
      if (!ref.current) return;
      setValue(getComputedStyle(ref.current).getPropertyValue(name).trim());
    };
    read();
    const watcher = new MutationObserver(read);
    watcher.observe(document.documentElement, { attributes: true, attributeFilter: ['data-theme'] });
    return () => watcher.disconnect();
  }, [name]);

  return [ref, value];
};

const Swatch = ({ name }) => {
  const [ref, value] = useValue(name);
  return (
    <Flex vertical gap={4} style={{ inlineSize: 132 }}>
      <div
        ref={ref}
        style={{
          blockSize: 40,
          borderRadius: 4,
          background: `var(${name})`,
          border: '1px solid var(--ant-color-border)',
        }}
      />
      <Typography.Text style={{ fontSize: 12, fontFamily: 'var(--ant-font-family-code)' }}>
        {value || '-'}
      </Typography.Text>
    </Flex>
  );
};

export default () => (
  <Flex vertical gap={20}>
    <Flex gap={12}>
      <div style={{ inlineSize: 88 }} />
      {levels.map((level) => (
        <Typography.Text key={level} strong style={{ inlineSize: 132, fontSize: 12 }}>
          {level}
        </Typography.Text>
      ))}
    </Flex>

    {meanings.map(([label, ...names]) => (
      <Flex key={label} gap={12} align="flex-start">
        <Typography.Text strong style={{ inlineSize: 88, paddingBlockStart: 10 }}>
          {label}
        </Typography.Text>
        {/* The key is the level, not the variable name: Neutral shows
            the same name twice, and React would then have two children with
            demselben Schluessel gemeldet. */}
        {names.map((name, i) => (
          <Swatch key={levels[i]} name={name} />
        ))}
      </Flex>
    ))}
  </Flex>
);
```

:::note[Neutral shows the same value twice]

Ant Design calls this meaning `info`; measured, it is `neutral`. It
carries no separate LIGHT level in our vocabulary, so BASE stands in - and the
table shows that rather than hiding it behind a computed shade.

:::

## The seven meanings

Six are above. The seventh is `accent`, which is for highlighting rather than
for status, and which therefore has no place in a severity row.

Two further meanings were measured and are deliberately absent: `assistance`
and `accentSecondary`. Across 22 measured pages, `assistance` paints nothing at
all and `accentSecondary` paints one
avatar background. Carrying twenty-two values no component reads would make
the vocabulary longer and not better.

`risk` is present for the opposite reason: it paints on a page we have - the
health indicator - and before it existed, our page wrote `color="orange"`,
which is a value from Ant Design in the middle of a page that otherwise has
none.

## Where the colours come from

None of these values is written twice. `tokens.ts` reads the extracted package;
everything else reads `tokens.ts`. What you see above is
`getComputedStyle(document.documentElement)` - the values actually in force on
this page, which is the only reading that cannot be out of date.
